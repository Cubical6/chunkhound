# Fork changelog

What `Cubical6/chunkhound` changes on top of `chunkhound/chunkhound`.
Upstream's changes are in `CHANGELOG.md`; the fork leaves that file as upstream
wrote it.

- One entry for each change a user of the fork notices. Add it in the same
  pull request, at the top of its heading.
- Each entry is one line that starts with a bold title: `- **Title** — text`.
  The release notes compare titles to show what is new since the last stable release.
- Remove an entry when upstream ships the same change.

## Added

- **Decision log** — Opt-in local JSONL file (`decision_log.enabled`, `CHUNKHOUND_DECISION_LOG__ENABLED`; default `.chunkhound/decisions.jsonl`; paths must resolve inside the project's resolved `.chunkhound/` directory and cannot be set remotely; refused paths disable logging with one warning and no fallback; rotated above `max_size_mb`, minimum 1 MiB, to `<filename>.1`) that records why searches and research runs went the way they did: the multi-hop or single-hop choice and why expansion stopped, commit-scoped semantic searches marked with `vector_source: "diff"`, each `code_research` run with only its own LLM usage even when runs share a provider concurrently (CLI token estimates remain separate), which follow-up questions and gaps were kept, and per chunk the rerank scores and the elbow-filter cutoff. Records hold queries, file paths and line ranges, never code. Rotation and appends are locked across processes through a `<filename>.lock` file next to the log, which stays in place; new log files and directories are owner-only on POSIX (existing permissions are unchanged), and non-finite scores are stored as JSON null. Off by default.
- **Fork release channels** — Every push to `main` publishes the wheels as the rolling `fork-latest` release. `fork-promote.yml` copies a checked `fork-latest` build, after approval, to a new and unchangeable stable release `fork-v<version>` (for example `fork-v6.1.1.dev198`) without rebuilding; the newest one is the repository's Latest release. All releases list the fork changes they add.
- **Upstream overlap check** — `scripts/fork_upstream_check.sh` lists open upstream pull requests that touch given paths and searches upstream issues and pull requests by topic.
- **pi-cli LLM provider** — `provider: "pi-cli"` runs the local pi CLI as a bare model, without tools, MCP, extensions, context files or a session. It is selectable for every LLM role through config, environment and the `--llm-*-provider` flags, needs no API key and has no default model: set one in `provider/id` form.
- **`chunkhound map --c4-only`** — Runs the full C4 analysis without planning or topic research, so it needs no database or embeddings. Existing topic files are kept.
- **Development cache for `map` and `autodoc`** — `--dev-cache` is opt-in. `chunkhound map --dev-cache` reuses the HyDE plan, even after code changes, and reuses topic research while its evidence files are unchanged; `--refresh-plan` generates and stores a fresh plan. `chunkhound autodoc --dev-cache` reuses cleanup, homepage and site structure results and passes the flag on to its internal map run.
- **MCP search strategy setting** — `mcp.search_strategy` (`CHUNKHOUND_MCP__SEARCH_STRATEGY`) selects `auto`, `single_hop` or `multi_hop` for semantic queries of the MCP `search` tool on both transports. With `single_hop`, a configured reranker is used by `code_research` only and plain searches make no rerank requests. The default `auto` keeps the existing behavior.
- **Cached C4 actor consolidation** — Utility-model group proposals, existing-member survivor choices and independent `same`/`different`/`unsure` pair decisions now consolidate people and external systems before manual corrections. Only `same` pairs merge; names, relations, citations and found status follow the surviving member without changing raw documentation, reference destinations or lock merge rules. Symmetric `keep_apart` pairs prevent direct and shared-target merges. Source-backed per-kind/group/pair caches support zero-call replay, read-only trials and one retry before an uncached conservative fallback; reports name merges, separation reasons and reuse/fallback counts.
- **C4 service-table actors** — Selected Markdown service tables now supply documented external systems and people through closed table/row utility-model decisions. Actor names come from the visible first cell, including inline formatting, with verified citations to the original row and directed `uses` relations. Checked documentation takes precedence over same-kind normalized duplicates; unchanged table previews and individual rows reuse cached decisions without changing raw documentation or the version-5 lock.
- **Cached C4 element decisions** — A closed utility-model check now classifies documented people and external systems before assembly, correcting kinds or dropping unsupported candidates while preserving raw documentation in the version-5 lock. Decisions reuse individual source-backed answers; changed evidence, prompts, validators or utility provider settings invalidate only the affected cache keys. Invalid answers retry once before retaining the original kind without caching the fallback. Trial runs are call-free and read-only; full runs prune unused decision entries after 30 days.
- **C4 assembly follows LLM merges before manual corrections** — Assembly now applies proposed external-system/person merges first, then remaps lock `drop`, `merge`, `names` and `descriptions` to surviving IDs. Colliding rules are deterministic and reported; a survivor's own name or description wins. Relations, citations and source status follow merges while static reference destinations remain unchanged. Version-5 locks can store `keep_apart` pairs and still load when the field is absent.
- **C4 curation overrides** — `overrides.drop` and `overrides.merge` in `.chunkhound/map.lock.json` remove or merge an external system or person; relations, citations and status follow, references stay in the evidence; invalid entries are skipped with a `C4-overrides:` report line; the lockfile stays version 5. The documentation step no longer turns a category, a role, a name from an example, or a library into an external system, so the next run asks that step again.
- **C4 documentation step defines what it extracts** — The sources no longer depend on what this run's research cites: every Markdown file in the scope counts, except history documents, tool instructions (`AGENTS.md`, `CLAUDE.md`), licenses and `prompts` or `vendor` directories, so unchanged documents give the same map without a call. The step now uses the C4 definitions of person and external system, reads tables of supported services as relations, and adds descriptions; documentation no longer creates containers or components. A changed prompt extracts again.
- **C4 map follows C4 more closely** — Relation titles now state a purpose: the titles step receives the names and descriptions of both elements and the files reached, and a changed titles prompt asks for new titles. A documentation term naming your own system, a container or storage joins that element instead of becoming a new one. An SDK that exists to call one external service is classified as an external system. The contract leaves out external systems and persons without a relation to the system, relations between a container and its own components, and container relations a component already shows; the report counts these and names what it left out, and the internal pair keeps them.
- **C4 contract for AutoDoc and source selection** — A full `chunkhound map` run now writes three C4 files, so AutoDoc can publish a map from mapper output: `<scope>_c4_model.json` is the version-1 contract that AutoDoc reads, and the internal pair is renamed to `<scope>_c4_map_model.json` and `<scope>_c4_map_evidence.json` (previously `<scope>_c4_model.json` and `<scope>_c4_evidence.json`). `--plan` runs write only the internal pair and leave an existing contract untouched; a full run removes a leftover `<scope>_c4_evidence.json`. The lockfile moves to version 4: each directory is now one building block, `tree_spec` and `group_membership` are gone, and there is no migration. `map` refuses an older lock with an error naming the file, so delete `.chunkhound/map.lock.json` and run again; this also discards its stored IDs and manual `overrides`. The C4 analysis now leaves out test directories, test-named files and `map`'s own output, and hidden directories and changelog-style files are no longer documentation sources. A new `c4` section in `.chunkhound.json` adds `exclude` patterns from the project root and `exclude_test_code` (default `true`). The index, research and map topics are unaffected.
- **C4 runtime discovery** — Detects executable Python, Node, Composer and Cargo packages and Docker runtime boundaries, with manifest citations, typed storage candidates and lock-preserving container IDs. Template package names are excluded; scopes without a recognized runtime receive a provisional container.
- **C4 deterministic grouping** — Groups files within explicit runtime roots without an LLM. Lock schema 3 persists previous file ownership independently of semantic components and explicitly records successful direct placements; replay preserves known groups while assigning newly introduced directories their own prefix-only groups.
- **C4 classification** — Classifies new dependencies, runtime and storage candidates using three bundled LLM voting rounds. Manual corrections and locked decisions skip calls; trial runs remain deterministic and call-free. Transient failures get one delayed voting attempt, then marked conservative fallbacks.
- **C4 documentation evidence** — Extracts documented actors, external systems, containers, components and relationships only with literal, line-verified quotations from scope READMEs and topic-cited Markdown. Unchanged source hashes reuse the lockfile without model calls; transient failures retry once before using a marked previous or empty outcome.
- **C4 pipeline** — Coordinates runtime classification, deterministic groups, semantic components, documentation, stable identity, coverage and relationship labels. Generated arrow labels support strict structured-output providers without changing the public model or lockfile format. Deferred transient failures retry once after other work; marked fallbacks remain visible but are excluded from caches. Unchanged inputs replay the last successful transition, including history and rename metadata, with identical JSON and no LLM calls; file-content, scope, HEAD, configuration, topic and override changes invalidate that transition. Trial runs perform no LLM calls and never produce a replacement lock.
- **C4 map output** — `chunkhound map` now writes `<scope>_c4_model.json` and `<scope>_c4_evidence.json` alongside Markdown topics, plus reusable decisions in `.chunkhound/map.lock.json`. Shared C4 and Markdown file selection honors repository-local Git `info/exclude`, including linked-worktree metadata, when Git-ignore is enabled. Research results expose synthesis-used file paths and chunk ranges to legacy source counts and C4 topic coverage, without duplicating source contents. Per-step reports show call-attempt reasons and accepted, sanitized validation-rejection, transient-error or fallback outcomes alongside the total C4 call count; they contain no prompt or answer text and do not measure research calls, tokens or costs. Use `--no-c4` for the previous Markdown-only behavior or `--no-markdown` to retain research and C4 coverage without publishing Markdown. `--plan --no-markdown` writes a deterministic trial without a database, LLM calls or lockfile changes. `--no-c4 --no-markdown` and `--combined --no-markdown` are rejected before work starts.
- **C4 lockfile workflow** — Keep reusable C4 decisions and manual `overrides` in the project-root `.chunkhound/map.lock.json`, independently of `--out` or the database path. To version the lock while ignoring the index and other generated state, add `.chunkhound/*` followed by `!.chunkhound/map.lock.json` to `.gitignore`; `map` never edits `.gitignore`. Trial runs leave the lock unchanged, and fallback decisions are not cached. Concurrent runs are not locked: the last writer wins.
- **Optional AutoDoc architecture maps** — AutoDoc now consumes the selected index's neutral version-1 C4 sidecar and publishes native LikeC4 full maps, overview/topic previews, direct topic targets and architecture search links. Producer identity, evidence and commit-pinned source links survive projection; missing or invalid models warn and leave an ordinary site without optional React/LikeC4 dependencies. Map sites bundle the pinned runtime and local fonts, with strict build-time DSL validation. Full regeneration removes only fixed map outputs attested by a previous enabled publication; assets-only refreshes presentation/runtime while preserving topic, map, DSL, search and navigation bytes.
- **Packaged AutoDoc map verification** — The existing wheel verifier now checks pinned LikeC4 archive/patch/license integrity, packaged resources and executable root/React/Vite exports through a temporary local-archive npm consumer. The existing wheel CI job runs this explicit distribution integration check with Node.js 24; maintenance instructions cover sdist rebuilds and outside-checkout installed-site proof. Missing or invalid fork artifacts fail instead of falling back to upstream.

## Changed

- **C4 decision and lock responsibilities** — A step-scoped decision runner now owns shared cache/provider/retry dependencies separately from each question's inputs. Lock snapshots, identity transitions and raw-document serialization are assembled separately, preserving replay, partial-merge recovery and manual override provenance without changing model or lock formats.
- **Astro 7 / Vite 8 documentation sites** — Upgraded both the AutoDoc template and project website to Astro 7.4.2, with Vite 8 supplied by Astro. Building either site now requires Node.js 22.23.4 or newer and npm 9.6.5 or newer; CI uses Node.js 24. Existing generated sites can refresh their template with `chunkhound autodoc --assets-only --out-dir docs-site/`, followed by `npm install` and `npm run build` in that directory. Markdown/GFM, syntax highlighting and the existing Mermaid major versions are retained.

## Fixed

- **Multi-hop thresholds take effect** — `multi_hop_min_candidates`, `multi_hop_score_degradation` and `multi_hop_min_relevance` (and their `CHUNKHOUND_RESEARCH_MULTI_HOP_*` variables) were loaded but ignored; multi-hop search now uses them. The defaults keep the previous behavior.
- **MCP progress for long tool calls** — code_research and other long tool calls now send progress notifications (research phases at most once per second, plus a heartbeat every 30 s), so clients with an idle timeout (Claude Code: 300 s over HTTP) no longer abort them. A slow client never delays the tool, and heartbeats stop after 10 minutes without real progress, so a hung tool still times out.
- **Out-of-range modification times no longer abort indexing** — A file dated far before 1970 or far in the future, outside the database's timestamp range, no longer makes the Rust index run fail with "Epoch seconds out of range"; its time is stored clamped to the nearest supported value.
- **Same-size edits of pre-1970 files on the Rust pipeline** — A file dated before 1970 that is edited without changing its size is re-indexed again; before, search kept returning its old content until a force reindex.
- **File stores after a failed compaction commit** — When a commit failed during auto-compaction, every later file store ran without a transaction until the daemon restarted, so a store that failed halfway kept the new content hash over stale or missing chunks and the file was never re-indexed. Auto-compaction also stayed off. Both now recover after the failed commit.
- **Files with a modification time before 1970** — An indexed file whose modification time is set before 1970 (for example by tar or rsync) is re-indexed again instead of failing with "Modification time cannot be negative" on every scan.
- **Realtime on watchdog 4.x** — On Linux with watchdog 4.0.x, realtime indexing uses inotify again instead of falling back to polling with "cannot import name 'UnsupportedLibcError'". As with watchdog 5.x and 6.x, inotify overflow detection reports `unavailable` there: changes the kernel drops when its event queue overflows are not re-indexed until the file changes again. Detection needs watchdog 7.1 or newer.
- **C4 output and git paths on Windows** — C4 files (lock, model, evidence, contract) are written with LF line endings on every platform, so the lock file is byte-stable. Git output is read as UTF-8, so a file with a non-ASCII name no longer costs its repository the source links on Windows.
- **Crashed compaction swap recovery** — A native DuckDB compaction swap that was interrupted is now recovered before the CLI preflight and before a connection opens, so an empty live database is no longer created over it.
- **Research source list** — `metadata.sources` of a research answer now lists the sources that were actually used in synthesis, not every retrieved candidate.
- **C4 added-actor reporting** — Decision reports now name each added table actor and its authoritative row citation, including cached replay, without changing extraction or decisions.
- **C4 empty Markdown headings** — Valid empty ATX headings no longer abort table decisions, including documents without tables. Empty headings still end preceding sections at their own level, so service-table context does not retain obsolete headings.
- **C4 template exclusion** — A Dockerfile beside a package with a placeholder name no longer promotes that template directory to a runtime container.
- **C4 scoped replay** — Fresh reference-resolution outcomes now invalidate transition replay when imports change between project files and external packages, including dirty target creation or removal outside the selected scope. Genuinely unchanged results still replay with identical JSON and no model calls.
- **C4 documented term provenance** — Documented element terms and relation endpoints must occur literally, as whole words, within their own verified citation span, with whitespace tolerance but no case folding or inferred names: `Go` no longer matches inside "Google". Cached documentation is revalidated before reuse, trial output or fallback, so earlier unsupported names cannot reappear through successful-transition replay; valid literal elements remain reusable without model calls. The stricter rule changes the step version, so the next run asks the documentation step again.
